# 校准发票与验收单对账班报

同机构同结算期精确配平，方案一致整组入账，余下待核

澄岭精密零件厂 · 财务结算室 校准机构按月开具服务费发票，车间按器具校准完工提交验收单。财务把两类单据合并导入，系统按校准机构与结算期分组，以整数分精确凑数：一张发票可配同组多张验收单，每张单据只能认领一次。系统先尽量多配平发票，枚举全部最优方案，只把所有方案一致的整组提交入账，其余留待核对并注明原因。

- 一张发票常对应多张验收单，人工凑金额容易漏单、错配或重复认领。
- 同额单据存在多种等价配法，未经比对直接入账可能选错整组。
- 晚到验收单补齐后手工重算，容易破坏已经入账的配对。
- 班报必须说清每组配对依据，以及每张待核单据为什么不能确认。

## 业务模块

| 模块 | 用途 |
|---|---|
| 对账值班台 | 查阅业务口径、处理步骤、账套概况与最新审计记录。 |
| 单据与导入 | 下载「澄岭厂校准发票与车间验收单.csv」模板并导入 UTF-8 CSV，保留数据指纹和原始行，查看发票/验收单台账。 |
| 对账计算 | 选择数据批次提交后台配对，可从批次列表追踪状态。 |
| 配对结果 | 查看建议确认整组、待核整组、待核发票与待核验收单，含配对依据、候选配法数与待核原因。 |
| 入账复核 | 复核主管确认方案一致整组入账；旧配法被拒时提示在最新批次重确认，重复提交不二次认领。 |
| 班报与待核 | 查看已入账整组（含依据、入账人）与实时待核单据，下载对账 CSV 交班。 |

## 演示流程

1. 11 月 22 日 08:00，财务导入发票与验收单，含岭南计量、东江检测院两个机构的两个结算期。
2. 岭南计量 10 月期发票 INV-2610-01（1200.00 元）由验收单 YS-1001、YS-1002 凑齐，整组唯一，进入建议入账。
3. 岭南计量 11 月期两张 500.00 元发票与两张 500.00 元验收单存在两种等价最优配法，方案不一致，全部留待核。
4. INV-2611-03（333.33 元）暂无满足金额的验收单组合，列入待核发票。
5. 主管在入账复核页确认方案一致整组，系统锁定发票与验收单；重复提交幂等跳过，不二次认领。
6. 导入晚到验收单 YS-1104（333.33 元）后重新计算，已入账整组原样保留，INV-2611-03 得到唯一配对。
7. 在班报与待核页查看配对依据、待核原因并下载对账 CSV。

## 计算口径

- 发票与验收单按校准机构、结算期（YYYY-MM）分组，跨机构或跨结算期不参与配对。
- 金额按整数分精确比较：发票金额必须等于其名下验收单金额之和；一张发票可配多张验收单，每张单据全程只能被认领一次。
- 可行配对中先最大化配平发票数，再最大化被认领验收单数；系统用 bitmask 动态规划统计全部最优方案，仅确认在所有最优方案中都出现的整组，其余列入待核并注明原因（无满足金额组合 / 最优方案不一致 / 无对应待配发票）。
- 单个机构+结算期的验收单上限 18 张，状态预算 40 万；超出会提示缩小结算期范围，避免组合爆炸。
- 晚到单据导入后的重算只处理待认领单据，已入账整组原样保留。入账与重算并发时，引用已变动单据的旧配法拒绝入账，可安全重试且不重复认领。

## 本地开发

| 组件 | 实现 |
|---|---|
| 前端 | Nginx 与原生 HTML、CSS、JavaScript。`frontend/src/pages` 放页面，`components/common` 放共用表格、图表及表单。 |
| API | Python 3.11、FastAPI、SQLAlchemy。`backend/src/domain` 放字段口径、配对引擎和演示数据，`routes` 放接口，`models` 放表模型。 |
| 后台 | 独立 Python worker，通过 Redis 唤醒，从数据库租约领取对账批次，CSV 写入共享卷。 |
| 数据 | MySQL 8 存储单据、批次、入账整组与审计。`backend/scripts/seed_demo.py` 可安全重复执行。 |
| 测试 | 配对引擎为纯标准库实现，`cd backend && python3 -m unittest discover -s tests -v` 可离线运行。 |

改动前端后执行 `docker compose up -d --build frontend`。改动接口或算法后执行 `docker compose up -d --build backend worker`，再刷新浏览器。使用 `docker compose down -v --remove-orphans` 会清除该项目的数据库、Redis 和报表卷。

`.env.example` 中的 `COMPOSE_PROJECT_NAME`、`FRONTEND_PORT`、`BACKEND_PORT`、`DB_PORT`、`APP_SUBNET` 控制项目隔离。后端 `constants/enums.py` 与前端 `src/constants/enums.js` 保持角色与运行状态一致。项目许可证见 `LICENSE`。
