# 001 初始表结构

应用首次启动以 SQLAlchemy 模型创建表与唯一约束。现有数据表只补建缺失表，升级到修改过字段的版本需要显式迁移。

- `users` 账号角色和加盐密码摘要。
- `datasets` 不可变导入批次，以名称和 SHA-256 去重，保留原始 CSV 行与数据指纹。
- `invoices` 校准机构发票台账，发票编号全局唯一；金额以整数分存储。
- `acceptance_notes` 车间验收单台账，验收单编号全局唯一；金额以整数分存储。
- `pairing_batches` 对账计算批次，记录运行租约、尝试次数、配对结果快照、导出文件与失败原因。
- `posted_groups` 已入账整组。`invoice_id` 与 `group_key` 各有唯一约束，保证一张发票只入账一次、同一整组不重复认领；`note_codes` 以 JSON 保存该整组认领的验收单编号。
- `audit_events` 记录登录、导入、对账计算与入账动作。

## 并发与一致性约束

- 发票只能通过 `posted_groups.invoice_id` 唯一约束入账一次；验收单编号出现在任一 `posted_groups.note_codes` 即视为已认领，导入修改已认领单据会被拒绝（409）。
- 入账在单事务内对涉及发票、验收单加行锁，并用「当前待认领单据重算结果」比对批次快照；依据变化的旧配法拒绝入账（409），可在最新批次上安全重试，重试对已入账整组幂等跳过。
- 对账批次通过 `attempt` + `lease_until` 租约领取，迟到的旧进程结果在落库时因 `attempt` 不匹配被丢弃。
